# P1 — отчёт о реализации и проверке

**Дата:** 10 ноября 2026 года. **Ветка:** `main`. **Коммит проверенного кода:** [`ea319d8`](https://github.com/klonadol/tgbot/commit/ea319d8a0759e825a213a2ca436f0e5bc66a46d4).

## Реализовано

- `src/tgbot/main.py` — одна точка запуска, aiogram 3, long polling, штатное закрытие HTTP-клиента, сессии бота и SQLite.
- `src/tgbot/config.py`, `.env.example`, `.gitignore` — настройки Telegram, адреса/модели/ключа LLM, единственного персонажа, таймаута, БД без публикации секретов.
- `src/tgbot/llm.py` — **настоящий** OpenAI-совместимый запрос `POST /chat/completions`, проверка ответа и диагностика 401/403, 429, 5xx, сетевых ошибок и таймаута.
- `src/tgbot/storage.py` — SQLite WAL, миграция версии 1, уникальность входящих сообщений, история после перезапуска, статусы ответа `pending/sent/failed/unknown` и фактический Telegram message_id при отправке.
- `src/tgbot/telegram.py` — текст личного чата → SQLite → контекст сообщений → LLM → Telegram → фиксация результата. Повторный входящий message_id не вызывает вторую генерацию и отправку.
- `requirements.txt`, `run.bat`, `README.md` — фиксированные зависимости, команды запуска на Windows и инструкция настройки.
- `tests/test_p1.py`, `.github/workflows/p1-tests.yml` — тесты поведения и проверки на Ubuntu/Windows.

## Проверки и результаты

- Локально: синтаксическая компиляция — успешно; 16 `unittest` — успешно. Здесь использовалась **локальная временная заглушка классов исключений aiogram**, так как установить пакет в этой среде не удалось.
- [GitHub Actions, первый прогон](https://github.com/klonadol/tgbot/actions/runs/42829487653): установлен реальный `aiogram==3.22.0`; Ubuntu — 16/16, Windows — 16/16, оба задания завершились `success`.
- [GitHub Actions, повторная проверка](https://github.com/klonadol/tgbot/actions/runs/42829866062): Ubuntu — 18/18, Windows — 18/18, оба задания завершились `success`. Добавлены проверка импорта точки запуска и проверка явного отказа Telegram API.
- В тестах с имитациями подтверждены: корректная сборка HTTP-запроса, продолжение контекста, дедупликация, запись статуса отправки с ID, ошибка Telegram, таймаут LLM, коды 401/403/429/5xx, изоляция контекста, рестарт SQLite.
- Содержимое исходных файлов в GitHub сверено с подготовленными локально файлами по Git blob SHA. Исходный `docs/ARCHITECTURE.md` оставлен без изменений.

## НЕ ПРОВЕРЕНО

- Реальное получение `Привет` в Telegram и фактическая доставка ответа до интерфейса пользователя.
- Осмысленный ответ настоящего LLM API и последующее связное продолжение в живом диалоге.
- Реальное поведение провайдера с неверным API-ключом и реальными лимитами.
- Работа `run.bat` с настоящими токенами, Ctrl+C и восстановление сессии на ПК владельца.

**Ограничения:** P1 обрабатывает только текст личных чатов. При неопределённом результате `send_message` исход не угадывается и отправка не повторяется вслепую. Входящее сообщение после падения остаётся в БД, однако незаконченный ответ не восстанавливается автоматически. Полноценные группы, изображения, память, запоминатель, судья и инициатива не реализованы (это P2–P7).

**Решение: P1 завершена частично.** Код и проверки с имитациями готовы, но обязательная живая приёмка из `docs/ROADMAP.md` ещё не проведена. Переходить к P2 до её подтверждения нельзя.
