# TG Bot — один персонаж с общей памятью

Проект Telegram-бота, который общается с друзьями от лица **одного вымышленного персонажа**, распознаёт изображения, запоминает разговоры и иногда пишет сам. Управление разговором происходит обычными сообщениями, без пользовательских команд.

> **Статус:** минимальный код P1 реализован; проверка с настоящими Telegram и LLM API ещё **НЕ ПРОВЕРЕНА**. Остальные фазы запланированы.

## Главная идея

- **Один персонаж, одна общая долговременная память** из всех разрешённых личных и групповых чатов. Факты, узнанные от одного человека, потенциально могут быть упомянуты другому — это осознанный выбор.
- **История диалога локальна для чата:** говоритель получает последние 20 сообщений соответствующего чата и подходящие записи из общей памяти.
- **Три гномика:** говоритель, запоминатель (после каждых 20 новых сообщений чата) и судья (проверяет схожие воспоминания).
- **Отдельная база знаний:** постоянные записи или записи, включаемые при подходящем поисковом запросе; автор — владелец бота.
- **Зрение:** фото и поддерживаемые Telegram-изображения попадают в совместимую с изображениями модель.
- **Инициатива:** бот может сам писать в ранее начатые личные переписки и доступные группы, но соблюдает ограничения частоты и тишины.
- **Один или несколько API:** единый диспетчер ограничивает параллелизм и не даёт фоновым гномикам блокировать ответ другу.

## Где подробности

1. [Архитектура и правила работы](docs/ARCHITECTURE.md) — модули, данные, память, гномики, зрение, инициатива, ограничения Telegram, сбои и конфиденциальность.
2. [План реализации по фазам](docs/ROADMAP.md) — зависимости, результаты, проверка пользовательского пути, критерии перехода и тестовые сценарии.

Основной порядок: приём и ответ → надёжная история нескольких чатов → зрение → база знаний → запоминатель → судья → инициатива → эксплуатационная проверка. Никакая поздняя фаза не считается готовой, пока пользовательский сценарий не работает целиком.

## Выбранный стартовый стек

- **Python 3.12+** и **aiogram 3** — Telegram Bot API, асинхронная обработка сообщений.
- **SQLite (WAL, внешние ключи, миграции)** — история, память, настройки, очередь фоновых работ, журнал.
- **SQLite FTS5 + векторное сходство** — поиск по тексту и смыслу; на небольшом объёме векторы допускается сравнивать в приложении, без отдельного векторного сервера.
- **HTTP-клиент ИИ** — отдельные настройки моделей для текста, изображений и эмбеддингов; допускается один провайдер и одна модель там, где её возможности подходят.
- **Long polling** на одном процессе для первой версии; более сложную инфраструктуру не добавлять преждевременно.

Конкретные версии зависимостей фиксируются при начале реализации и проверяются на реальном запуске, а не предполагаются заранее.

## Как начать пользоваться

1. Через [@BotFather](https://t.me/BotFather) создать бота и получить секретный токен.
2. Локально настроить токен бота, ключ ИИ, модели и параметры персонажа; секреты **никогда не добавлять в GitHub**.
3. Запустить приложение на своём ПК. Оно должно работать постоянно, чтобы принимать сообщения и проявлять инициативу.
4. Друг открывает бота и впервые отправляет сообщение (в Telegram допускается стандартное «Начать»); после этого возможны инициативные сообщения. Для групп нужно добавить бота и правильно настроить права и режим конфиденциальности.
5. Сообщить участникам, что бот — ИИ и что его общая память может переносить информацию между чатами. Не отправлять ему пароли, коды, токены и другие чувствительные сведения.

**Пользовательских команд для управления памятью не будет.** Обслуживание и удаление данных предусматриваются через локальные средства владельца, не через публичные команды Telegram.

## Ограничения Telegram

- Обычный бот не может первым открыть личный диалог с человеком, который ему ещё не писал.
- Для чтения обычных сообщений в группе может потребоваться отключение Privacy Mode у @BotFather; иначе бот видит лишь часть сообщений. Сообщения других ботов, как правило, недоступны.
- В обычном Bot API нельзя рассчитывать, что удалённые пользователями сообщения автоматически исчезнут из собственной базы.
- Telegram «доставил запрос в приложение» и «пользователь увидел ответ» — разные состояния; необходима диагностика отправки.

Источники: [Telegram Bots](https://core.telegram.org/bots), [Telegram Bot FAQ](https://core.telegram.org/bots/faq), [Telegram Bot API](https://core.telegram.org/bots/api), [aiogram](https://docs.aiogram.dev/en/latest/).

## Не входит в исходный объём

Несколько персонажей, управление через команды Telegram, автоматизация личного пользовательского Telegram-аккаунта, голос/TTS, самостоятельные действия в интернете, самостоятельная переустановка и сложная микросервисная инфраструктура. Их не добавляют без отдельного решения.


## P1: запуск минимального бота на Windows

**Статус:** код P1 добавлен; сценарий с настоящими Telegram и LLM API ещё **НЕ ПРОВЕРЕН**. Следующие фазы не реализованы.

Понадобятся Python 3.12, доступ в сеть, токен бота от [@BotFather](https://t.me/BotFather) и OpenAI-совместимый API (например, облачный сервис или локальная Ollama `/v1`). Не размещайте токены в GitHub или сообщениях. Перед использованием предупредите друзей, что сообщения сохраняются локально и передаются LLM-провайдеру; в будущих фазах общая память сможет переносить сведения между чатами.

1. В PowerShell из папки репозитория выполните `py -3.12 -m pip install -r requirements.txt`.
2. Скопируйте `.env.example` в `.env` (`Copy-Item .env.example .env`), укажите `TELEGRAM_BOT_TOKEN`, `LLM_BASE_URL`, `LLM_MODEL`, для облачного провайдера также `LLM_API_KEY`. Для Ollama локально — `LLM_BASE_URL=http://127.0.0.1:11434/v1`, `LLM_API_KEY` можно не задавать. Адрес — **базовый URL**, без `/chat/completions`.
3. Измените `CHARACTER_PROMPT` в `.env`, чтобы задать единственного персонажа. Все пользовательские сообщения в P1 — личные текстовые. Группы, фото, долговременная общая память и инициатива ещё не подключены.
4. Запустите `run.bat` (или установите `PYTHONPATH=src` и выполните `py -3.12 -m tgbot.main`). Для штатной остановки нажмите **Ctrl+C** в консоли. Не запускайте два экземпляра с одним токеном.

База по умолчанию: `data/tgbot.sqlite3` (WAL); `.env`, БД и её служебные файлы игнорируются Git. Папку `data` не удаляйте между запусками. Ошибка LLM показывается пользователю кратким уведомлением, подробная категория ошибки доступна в консоли без API-ключа. При неопределённом исходе отправки Telegram бот **не** повторяет отправку вслепую.

Локальные тесты без настоящих API: в PowerShell выполните `$env:PYTHONPATH='src'; py -3.12 -m unittest discover -s tests -v`. Успешные тесты не подтверждают реальную доставку через Telegram.
